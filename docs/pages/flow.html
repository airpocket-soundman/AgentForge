4. 自己拡張フロー

このページは初期構想（参考資料）。 ワーカー・パイプライン・承認フロー・安全装置の 正本は 5b. ワーカー定義・運用ルール／5c. コード規約（到達点はリポジトリ直下の VISION.md）。 記述が食い違う場合は正本に従ってください。

「タスク管理を追加して」の一言から、AI が計画し、ワーカーに委任し、Cloud Run に preview し、承認後に反映、要らなければ巻き戻すまでの 1 サイクル。

図 4-1. 自己拡張サイクル。すべての操作は Audit Log に残り、preview と active を分離。

進捗はいつでも即答

長時間処理は Cloud Tasks に切り出すため、作業中でも Reception が Firestore の task_runs を読んで即答します。「進捗どう？」→「Programmer が Task API を実装中、次は preview です」。

中止も安全に

「中止して」で cancel_requested=true を立て、未実行タスクは Control Plane が削除、実行中 Worker は協調停止。queue purge のような広範囲操作は AI に許可しません。

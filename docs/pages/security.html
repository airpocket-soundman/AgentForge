6. 安全設計

このページは初期構想（参考資料）。 ワーカー・パイプライン・承認フロー・安全装置の 正本は 5b. ワーカー定義・運用ルール／5c. コード規約（到達点はリポジトリ直下の VISION.md）。 記述が食い違う場合は正本に従ってください。

この作品の差別化点。AI に Google Cloud の強権限を直接渡しません。AI は判断・申請のみ、実行は限定権限のゲートが行います。

図 6-1. 4 層の権限分離。誤操作は「絶対に起こさない」ではなく「復旧不能を許さない」設計。

サービスアカウント分離

SA主な権限
core（reception/orchestrator/control-plane）Firestore read/write、Cloud Tasks enqueue、Tool Gateway invoke
tool-gatewayCloud Build 起動、Artifact Registry 書込、Cloud Run preview 更新、Storage 操作
workertask state 更新、workspace read/write、Tool Gateway invoke
generated-runtime生成 API 実行に必要な最小権限のみ

巻き戻しの隔離

Snapshot / Rollback 領域は AI から分離。AI は巻き戻しを提案できても、Snapshot Store を削除・改変できません。破壊的操作の前には自動 checkpoint を作成します。

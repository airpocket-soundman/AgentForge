3. システム構成図

ワーカーの定義・運用ルールの正本は 5b／コード規約は 5c。 本ページは現行実装の構成（点線＝計画中）。

フロントは Firebase Hosting、ロジックは Cloud Run、状態は Firestore、生成は Gemini API。AI ワーカーは MCP 的プロトコルで協業し、公開は必ず人間の承認を通ります。

図 3-1. 現行構成。5 種の AI ワーカーが 1 つの Cloud Run サービス内で MCP 的プロトコル（worker bus）により協業し、Control Plane が承認・版・監査を司る。

通信とコスト（scale-to-zero）

ブラウザ⇔バックエンドは REST/HTTPS。チャットは状態をポーリングし（このポーリングが Receptor の停滞監視ティックを兼ねる）、アプリを閉じればポーリングも監視も止まる＝アイドル時ほぼ ¥0（Cloud Run min=0）。ワーカー間は MCP 的な request/report（worker bus・スキーマ検証・task_id 相関）で、これは内部契約であり外部 MCP サーバではありません。

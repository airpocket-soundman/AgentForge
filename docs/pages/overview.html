1. 概要

AgentForge は、会話するだけで自分専用のアプリを生み・育てられる「自己拡張するスーパーアプリ」です。裏側では複数の AI ワーカーが設計・実装・検証・レビュー・デプロイ（DevOps）を安全に代行します。

一言で言うと

ユーザーがチャットで「計算機を作って」「タスクの色分けを追加して」と言うだけで、AI ワーカー群が 受付・具体化 → 設計案 → コード生成 → 動作検証＋レビュー → プレビュー → 承認公開 → 版保存・巻き戻し まで回し、アプリ自身が機能を増やしていきます。

本質は「再帰的・自己言及的なアプリ構造」。 使う場所＝作る場所。アプリの中での会話が、そのアプリ自身の機能（ミニアプリ）を生み・育て・巻き戻す。 生成されたミニアプリにも専属の AI ワーカーが付き、その中からさらに改変を頼める。

対象ユーザーと課題

  • ペルソナ：一般の非エンジニア。自分好みのアプリが欲しいが、ストアで探すのは面倒な層。
  • 課題：単純な計算機や PDF ビューワですら広告まみれでうっとうしい。微妙に好みと違う。 かといって自作するスキルはない。
  • 価値：「だったら自分で作って解決」を会話だけで成立させる。広告ゼロ・自分仕様・ 気に入らなければ言葉で直す・要らなければ安全に戻す。

提供価値の三角形

観点内容
ユーザー体験自然言語だけでアプリを生み・育てる（3つの承認ゲートで人間が常に主導）
技術的価値多 AI ワーカー（Receptor / Orchestrator / Tester / Reviewer / Specialist）が DevOps サイクルを協業代行
主張判断・分解・委任・検証・公開・巻き戻しまで AI が一貫制御しつつ、人間の承認なしには公開しない

“AI エージェントである必然性”

決め打ちの自動化と違い、曖昧な自然言語要求から「何を作り・どう分解し・どのワーカーに振るか」を 非決定的に判断する必要がある。受付の具体化・設計・生成・受け入れ条件の検証・規約と設計適合のレビュー・ 停滞の監視回収——それぞれ異なる判断を担う複数エージェントの協業そのものが本作の中心。

いま動いているもの（テスト環境で検証済み）

  • 3つの人間ゲート（受付確認「お願い」／設計承認「これで作って」／公開承認「反映して」）
  • 受け入れ条件つき設計案 → Tester が条件ごとに ✅/❌、Reviewer が規約＋設計適合をレビュー
  • プレビューへの修正ループ・差分パッチ改変・要求台帳（過去の依頼を壊さない）
  • 公開ごとの版スナップショット・「戻して」で直前版へ巻き戻し・変更履歴
  • 停滞の自発監視（無音時間ベース）→ ①停止/②待つ/③再トライ をユーザーが選択
  • ステータスモニター（ワーカー状態・待機理由・使用モデル）

9. DevOps / CI-CD

「まわす・とどける」を担う部分。GitHub への push を起点に Cloud Build が検証・ビルドし、Cloud Run に preview → 承認 → active で届けます。

図 9-1. CI/CD パイプライン。preview と active を分け、本番反映の前に必ず人間の承認を挟む。

2 つのデプロイ対象

対象パイプライン
AgentForge 本体（core / worker / web）GitHub → Cloud Build → Cloud Run / Firebase Hosting（継続デプロイ）
生成機能（タスク管理 等）MVP は view_manifest 方式で再ビルド不要。加点で Programmer が実コード → Cloud Build → preview

状態の段階

pending → building → preview → active → disabled → archived。AI に許可するのは原則 soft disable まで。Cloud Run service の delete は禁止し、不要な機能はトラフィック 0 で保持します。

コスト・暴走対策

  • task ごとに build 上限、worker retry 上限
  • Cloud Run は scale-to-zero（Reception のみ必要なら min=1）
  • 審査期間（〜7/24）はデプロイ URL を落とさない

10. 開発環境

別 PC でも同一環境を再現できるよう、開発環境はすべてコードとして記録。開発＝Dev Container、本番＝Cloud Run コンテナで統一し、parity を担保します。

図 10-1. dev=prod。開発も本番もコンテナで統一。

採用バージョン（ピン留め）

ツールバージョン定義場所
Python3.12.xDev Container / backend Dockerfile
Node.js24.x.nvmrc / devcontainer feature
gcloud / firebaselatestdevcontainer feature / postCreate
Python 依存固定backend/requirements.txt

別 PC での再現（これだけ）

  1. Docker Desktop をインストール（PC ごとに 1 回）
  2. git clone
  3. VS Code で「Dev Containers: Reopen in Container」
  4. 初回ビルドで依存まで自動構築 → 完了
本番（Cloud Run）はコンテナ実行。開発もコンテナに揃えることで「ローカルで動いたのに本番で壊れる」を避け、別 PC への移行も容易。

詳細な正式記録はリポジトリの ENVIRONMENT.md を参照。
